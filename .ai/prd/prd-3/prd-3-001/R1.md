# R1 · D1 schema

## 表清单
1. `students(id PK, name, created_at, updated_at)`
2. `classes(id PK, name, created_at, updated_at)`
3. `enrollments(id PK, student_id, class_id, status, created_at, updated_at)` + 索引(student_id)
4. `tasks(id PK, name UNIQUE, type, max_score, created_at, updated_at)`
5. `trainings(id PK, name, date, is_current, created_at, updated_at)` + 索引(is_current)
6. `training_students(training_id, student_id)` PK 组合
7. `training_tasks(training_id, task_id, rounds)` PK 组合
8. `mocks(id PK, training_id, name, date, competition_type, type, [group], participant_count, tasks_json TEXT, comments_json TEXT, schedule_json TEXT, created_at, updated_at)` + 索引(training_id)
9. `mock_scores(id PK, mock_id, student_id, task_id, round, score, time, updated_at)` + 索引(mock_id, student_id)  ← **独立成绩表**
10. `meta(key PK, value)`（schema_version / last_import_at / is_current）

## 学习要点
- 实体表规范化（id 稳定）vs JSON 列（低频嵌套数据）
- **scores 拆表原因**：学生远程提交 = 增量写单行，避免整坨 JSON 全量重写
- 索引作用：`WHERE mock_id=? AND student_id=?` 走索引，不扫全表，省 D1 rows_read
- `rankings` 是派生数据 → 不落库，前端 Analysis 现算，避免双端不一致
- `updated_at` 为未来增量同步/冲突检测预留
